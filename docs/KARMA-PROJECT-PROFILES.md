# 1. ValueCurator

## Project name
ValueCurator — Verifiable Policy & Safe Execution Infrastructure

## One-liner
Open infrastructure for safer AI-assisted financial operations through evidence-aware data, deterministic policy checks, explicit human authorization and auditable execution boundaries.

## Project description
AI agents and automated financial workflows increasingly interact with market data, protocols and assets. Yet a correct recommendation does not guarantee a safe action: data may be stale, confidence may be weak, permissions may be ambiguous, and execution boundaries may be compromised.

ValueCurator explores an auditable architecture that separates observation, analysis, policy evaluation, human authorization, signing and execution. Its technical direction includes provenance-aware oracle inputs, deterministic policy gates, explicit owner/operator/agent permissions, reproducible test scenarios and signed evidence of decisions.

The project aims to publish reusable open-source components, schemas, test cases and integration documentation. The public-good scope will be kept separate from hosted services, bespoke integrations or other commercial work.

## Problem
AI-assisted financial systems need verifiable controls between information and action. Without these controls, stale data, unsafe instructions or excessive permissions can turn a useful agent into an operational risk.

## Approach
- Model data freshness, confidence and provenance explicitly.
- Separate recommendation from authorization and execution.
- Apply deterministic, fail-closed policy checks.
- Make owner, operator and agent permissions inspectable.
- Test adversarial and degraded-data scenarios.
- Publish reusable SDK components, examples and integration guidance.

## Intended beneficiaries
Developers building AI agents, DeFi applications, protocol integrations and financial automation systems that require explicit authorization and auditable behavior.

## Current stage
Research / prototype / integration validation. This is not a claim of production readiness, completed independent audit or live mainnet custody.

## Public-good outputs
- Open policy and permission schemas.
- Reusable policy-gate components and examples.
- Oracle freshness/provenance test cases.
- Threat model and adversarial test harness.
- Developer documentation and reproducible demo.

## Funding use
Funding would support scoped open-source engineering, security testing, documentation, integration work and public demonstrations. Commercial hosting or bespoke services must be budgeted separately.

## Suggested tags
AI agents; DeFi; security; developer tooling; oracles; Solana (only if the current build includes a substantive Solana integration); open source.

# 2. Farcaster Commons Lab

## Project name
Farcaster Commons Lab — Conversation-to-Contribution Experiment

## One-liner
An open experiment converting social discussion into reviewed, reusable public-repository contributions with transparent provenance and evidence.

## Project description
Open ecosystems generate abundant discussion, but attention does not automatically become useful work. Farcaster Commons Lab tests a practical bridge from conversation to contribution: identify a concrete problem, publish a bounded work package, invite participation, review the resulting artifact in GitHub, record evidence and measure whether the work is reused.

The experiment treats Farcaster as a discovery and coordination surface, GitHub as the production and review system, and GrantOS as the funding and evidence orchestration layer. The first cycle should be deliberately small: one problem, one work package, one accepted contribution and one public evidence record.

## Problem
Communities often lack a transparent, low-friction mechanism to convert discussion and intent into accepted work, contributor recognition and reusable public goods.

## Approach
1. Identify one ecosystem-relevant problem.
2. Define a bounded task, owner, estimate and acceptance test.
3. Publish the task in GitHub and invite contributors through Farcaster.
4. Review and accept contributions through normal repository workflows.
5. Record artifact provenance and evidence level.
6. Measure reuse, contributor retention and downstream outcomes.

## Intended beneficiaries
Open-source maintainers, Web3 communities, public-goods funders, independent contributors and ecosystem coordinators.

## Current stage
Experimental pilot. Do not claim ecosystem-scale adoption, causal impact or sustained contributor retention until measured.

## Public-good outputs
- Conversation-to-contribution workflow.
- Contribution and evidence schemas.
- Public experiment log and methodology.
- Reusable task templates and review protocol.
- Open-source artifacts produced during the experiment.

## Success measures
- Number of work packages published with acceptance criteria.
- Number of unique contributors submitting work.
- Number of contributions accepted after review.
- Median time from task publication to accepted contribution.
- Percentage of accepted artifacts with reproducible evidence.
- Number of independent projects reusing an artifact.

# 3. Nodespace / DAO Embassy

## Project name
Nodespace — Agentic Coordination & DAO Embassy Infrastructure

## One-liner
Open research and prototyping for accountable coordination among people, AI agents and institutions through structured roles, provenance, commitments and contribution records.

## Project description
Collaboration across communities, DAOs and AI agents is often fragmented across conversations, documents and tools. Important context is lost, authority is unclear, and decisions are difficult to trace to accountable actions.

Nodespace explores a structured coordination layer in which participants and agents have explicit roles and mandates, interactions preserve provenance, and commitments can be converted into verifiable work. The DAO Embassy concept provides an institutional metaphor and prototype direction for representing communities and their authorized agents without pretending that a software agent automatically has legal or governance authority.

The initial work is research and specification-led. A fundable pilot must narrow the scope to one workflow and demonstrate it with real participants.

## Problem
Multi-party and agent-assisted collaboration lacks portable context, clear authority boundaries and a reliable path from conversation to accountable action.

## Approach
- Define participant, agent, role and mandate schemas.
- Prototype a structured diplomatic inbox and registry.
- Convert selected conversations into proposals, tasks and commitments.
- Preserve provenance, consent and authorization boundaries.
- Record contribution and decision histories.
- Validate one workflow with real participants before expanding.

## Intended beneficiaries
DAOs, open-source communities, ecosystem organizations and teams coordinating human and AI-agent work across institutional boundaries.

## Current stage
Exploratory / specification-led. Do not describe as a deployed coordination network or adopted DAO infrastructure until a working pilot and external users exist.

## Public-good outputs
- Open coordination and mandate schemas.
- DAO Embassy charter and role specifications.
- Conversation-to-contribution workflow.
- Prototype and reproducible case study.
- Governance, consent and provenance documentation.

## Success measures
- One workflow specified and tested with real participants.
- Number of commitments with an accountable owner and evidence link.
- Percentage of commitments completed or explicitly closed.
- Time from decision to accountable task creation.
- Number of independent communities reusing a schema or workflow.
