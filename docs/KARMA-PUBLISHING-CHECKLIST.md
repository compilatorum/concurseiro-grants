# Karma Publishing Checklist — GrantOS

Use this checklist as the operational bridge between GrantOS and the Karma platform.

## Phase A — Before creating a project profile

- [ ] Select one coherent project (do not merge unrelated repos into one profile).
- [ ] Confirm project owner and maintainers.
- [ ] Confirm canonical repository URL and visibility.
- [ ] Inspect actual license and IP constraints.
- [ ] Confirm project stage and distinguish shipped vs planned.
- [ ] Draft one-liner, problem, approach, beneficiaries and public-good outputs.
- [ ] Add team information only with consent.
- [ ] Define one or more measurable impact criteria.
- [ ] Prepare two or three evidence links that support the core claims.
- [ ] Remove unverified claims about partnerships, users, deployments, funding or audits.

## Phase B — Before adding a grant

- [ ] Confirm the specific program and official source.
- [ ] Confirm application status: draft, submitted, under review, approved, rejected or withdrawn.
- [ ] If approved, record award amount, currency, date and conditions.
- [ ] If disbursed, record amount actually received and transaction/payment evidence.
- [ ] Define funded work package and budget allocation.
- [ ] Check overlap with other funders and disclose co-funding.
- [ ] Add only the milestones funded by that grant.

## Phase C — Before publishing milestones

- [ ] Each milestone has one concrete deliverable.
- [ ] Each milestone has a measurable acceptance test.
- [ ] Each milestone has a credible time window and owner.
- [ ] Dependencies and out-of-scope items are explicit.
- [ ] Proof of completion is a stable, public artifact.
- [ ] Larger milestones are decomposed into smaller reviewable steps.
- [ ] No milestone implies a commitment that has not been resourced.

## Phase D — Before publishing an update

- [ ] State the reporting period.
- [ ] Describe only what changed.
- [ ] Link evidence for completed claims.
- [ ] Label blockers and risks.
- [ ] Separate output, outcome and impact.
- [ ] Disclose negative or inconclusive results when relevant.
- [ ] State the next bounded action.
- [ ] Avoid social engagement metrics as primary proof of impact.

## Phase E — Monthly reconciliation

- [ ] Compare Karma project/milestone records with GitHub.
- [ ] Reconcile awards and disbursements with the funding ledger.
- [ ] Refresh official opportunity status in GrantOS.
- [ ] Review evidence links and public accessibility.
- [ ] Update impact indicators with period and denominator.
- [ ] Archive submitted applications and accepted milestone versions.
- [ ] Check that no cost or deliverable has been charged twice.

## First publishing order

1. ValueCurator — strongest technical fit, but verify repository, current implementation and Solana relevance before adding ecosystem tags.
2. Farcaster Commons Lab — publish with a small experimental scope and baseline.
3. Nodespace — publish as exploratory/specification-led until a demonstrable pilot exists.

**Important:** These files prepare the content. They do not create Karma accounts, project profiles, grants, milestones or attestations. Those records must be created in Karma by an authorized project owner.
